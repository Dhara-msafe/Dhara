# RCA — Redeploy failed at pull_source (invalid Expo version)

## Deployment
- Deployment: bns-know-your-rights
- Failed run_id: bc596f13-3eba-466c-addc-d15961752e59 (type: redeploy)
- Last healthy run (still live): f712f082-568d-4145-81ec-166745a70d9c
- Deployed URL (unchanged, old backend still serving): https://bns-know-your-rights.emergent.host

## Failed step
`pull_source` — failed in ~9s, before any image build / EAS lane ran.

## Root cause
The deployer's mobile-config validator rejected the app's Expo version string:

```
invalid mobile app config: app.json expo.version "1.0.0-qa" is not a valid version
(expected e.g. 1.0.0) (type: V3MobileConfigInvalid, retryable: false)
```

Expo's `version` must be a plain semantic version `MAJOR.MINOR.PATCH` (e.g. `1.0.0`).
The value `1.0.0-qa` carries a `-qa` pre-release suffix, which the validator does not accept.
This is a static config validation at pull_source — it is independent of backend code, the
Docker build, and the manifest set. It will fail identically on every retry until the version
string is corrected in source.

## Why I did not fix it here
- This is a SOURCE fault (the value lives in the user's Expo config: `app.json` `expo.version`,
  or the `version` returned by `app.config.js` if the project generates app.json dynamically).
- It cannot be fixed by a deployment manifest override, and it cannot be fixed by the deployer agent.
- Eph-pod reproduction was not possible: `pull_source` failed, so no complete source archive was
  staged (spawn returned eph_source_access_failed on retry). Reproduction is unnecessary — the
  error is a deterministic, self-explanatory config validation.

## Fix (for E1 to apply in source, then re-trigger deploy)
Set a valid semver version with no pre-release/build suffix.

- If the project uses a static `app.json`: change
  `"expo": { "version": "1.0.0-qa", ... }` → `"expo": { "version": "1.0.0", ... }`
- If the project uses `app.config.js` (this template, `expo_mongo_base_image_eas`, generates
  app.json from `app.config.js`): find where `version` is set (e.g. `version: "1.0.0-qa"`) and
  change it to `version: "1.0.0"` (or any desired `MAJOR.MINOR.PATCH`).

Note: the store build number / versionCode is managed by Expo server-side, so only the
human-readable `version` needs to be a clean semver here. After the edit, re-trigger the redeploy.
