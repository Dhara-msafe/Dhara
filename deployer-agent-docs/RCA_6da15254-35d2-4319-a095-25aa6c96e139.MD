# RCA — Deploy run 6da15254-35d2-4319-a095-25aa6c96e139 (bns-know-your-rights)

## Outcome
Redeploy FAILED at `build_image` (EAS OTA-update lane, inside Cloud Build). A failed run is never promoted — the previous healthy backend (run b5fbbc3b) is still live at https://bns-know-your-rights.emergent.host. No production impact.

## Symptom (as reported)
`build_image` failed. The surfaced excerpt highlighted:
`Failed to get Git root path with git rev-parse --show-toplevel ... project:init command failed.`

## Root cause (real cause ≠ the git warning)
The git-root line is a **non-fatal warning** — eas-cli falls back to the working directory and continues. The build actually died on `eas.json` **schema validation** during `eas project:init`. Build log lines 301-303:

```
- "build.closed_testing.android.buildType" must be one of [apk, app-bundle]
- "build.production.android.buildType" must be one of [apk, app-bundle]
    Error: project:init command failed.
```

`frontend/eas.json` sets the Android `buildType` to the invalid value `"aab"` in two profiles. EAS accepts only `apk` or `app-bundle` for `android.buildType` (the App Bundle value is spelled `app-bundle`, not `aab`).

Current (broken) content:
```json
"closed_testing": { "distribution": "internal", "android": { "buildType": "aab" } },
"production":     { "distribution": "store",    "android": { "buildType": "aab" } }
```

## Fix (source — E1 to apply in the preview/source env)
In `frontend/eas.json`, change `"buildType": "aab"` → `"buildType": "app-bundle"` in BOTH the `closed_testing` and `production` Android profiles:

```json
"closed_testing": { "distribution": "internal", "android": { "buildType": "app-bundle" } },
"production":     { "distribution": "store",    "android": { "buildType": "app-bundle" } }
```
(The `development` and `internal_qa` profiles already use valid `apk` — leave them.)

## Verification performed
In the eph sandbox I applied the sed replacement to `/app/scratch/frontend/eas.json` and confirmed all four build-profile `android.buildType` values are now within the EAS enum `{apk, app-bundle}` (JSON parses, assertion passed). `eas project:init` itself could not be run end-to-end in the sandbox (no Expo token/credentials there), but the failure was a purely local schema check whose valid enum is quoted verbatim from EAS's own error, so the corrected value resolves it.
